# Прогон по датасету организаторов

Каждый из 21 примера датасета ([docs/task](../../docs/task/TASK.md)) прогнан через те же шаги, что и запись выпуска: страница читается так же, как источник, модель (`gpt-oss:120b`) ставит оценку и тип записи и пишет карточку или сводку для аудитории примера, номера уязвимостей сверяются с CISA KEV и БДУ, карточка проверяется по тексту. Рядом стоит «желаемый вывод» из датасета. Скрипты: `scripts/dataset_json.py`, `backend/scripts/dataset_run.py`, `scripts/dataset_report.py`; сырые ответы в [run.json](run.json).

## Итог

- Прочитано страниц: 19 из 21. Не прочитано: specialist-3 (сайт ответил HTTP 202); management-8 (сайт ответил HTTP 401).
- Специалисты, атаки и уязвимости: тип совпал в 6 из 6, приоритет в 4 из 6.
- Специалисты, посты Telegram: датасет кладёт их в группу «Инфо» по источнику, Scrap&Grep определяет тип по содержанию, поэтому пост об уязвимости получает карточку уязвимости и ссылки из поста, как в желаемом выводе.
- Руководство: признаков датасета найдено 22 из 32, лишних поставлено 13.

Где Scrap&Grep расходится с датасетом и почему, видно в разборе ниже. Два расхождения - ошибки самого датасета, а не модели: у specialist-4 (Axios) в датасете указан CVE-2025-59287, это уязвимость WSUS из specialist-7; у specialist-3 страной жертвы назван РФ при атаке на Европу и Юго-Восточную Азию. У specialist-7 датасет пишет «эксплойта нет», а CVE-2025-59287 с 24 октября 2025 года в каталоге CISA KEV: приоритет у нас выше по правилу самого датасета. У specialist-4 датасет пишет «публичный эксплойт», а на странице dbugs, по которой собран пример, после заголовка «Exploit» нет текста: признак, видимо, показан значком. Модель его не видит, и запись получает средний приоритет.

|---|---|---|

Конфиденциальный XSRF-TOKEN, хранящийся в файлах cookie, случайно включается в HTTP-заголовок X-XSRF-TOKEN для каждого запроса, отправляемого на любой хост, что позволяет злоумышленникам просматривать конфиденциальную информацию.

Ограничьте доступ к конфиденциальной информации, хранящейся в файлах cookie, чтобы свести к минимуму риск использования уязвимости. Не используйте переменную XSRF-TOKEN в уязвимом HTTP-заголовке до устранения проблемы.
> 6. Наличие эксплойта: да, публичный эксплойт
> 7. Идентификатор уязвимости CVE: CVE-2025-59287
> 8. Оценка CVE: 7,8
> 9. Метрики CVSS: CVSS v2.0 AV:N/AC:L/Au:N/C:C/I:N/A:N
> 10. Последствия компрометации сервиса: удаленный доступ к конфиденциальной информации

Уязвимость позволяет удалённому атакующему получить неавторизованный доступ к XSRF-TOKEN, включаемому в заголовок X-XSRF-TOKEN для всех запросов.

- **Уязвимость:** уязвимость в Axios+2
- **Затронуто:** Axios версии 0.8.1-through-1.5.1
- **Обновление:** нет данных
- **Временные меры:** Отключить автоматическое включение XSRF-TOKEN в заголовок X-XSRF-TOKEN; ограничить доступ к cookie-файлам с XSRF-TOKEN; не использовать переменную XSRF-TOKEN в запросах до появления патча.
- **Эксплойт:** нет
- **Идентификаторы:** CVE-2023-45857
- **CVSS:** 7.8
- **Последствия:** Утечка конфиденциального XSRF-TOKEN, возможность проведения CSRF-атак и доступа к защищённым ресурсам.
