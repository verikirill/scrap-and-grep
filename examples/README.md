## Две аудитории и как часто они читают

Жюри описало две аудитории: технари читают подробно и часто, руководство - тезисно и реже. Четыре выпуска собраны 3 октября 2026 года консолью на `gpt-oss:120b` по данным стенда, 87 источников: <!-- LATER: дата сборки и число источников стенда после пересборки (в каталоге по умолчанию 107) -->

```bash
docker compose run --rm cli digest --audience specialist --days 1
```

Выпуск специалисту начинается с разделов «Атаки» и «Уязвимости» с приоритетом и карточками. Выпуск руководству начинается с блока «Что это значит для нас», записи в нём по одному-два предложения, без номеров уязвимостей и других технических обозначений. В начале каждого файла - YAML с профилем, периодом, моделью и счётом публикаций, в конце, под `<details>`, - кандидаты, которые не вошли, с оценкой и причиной. «Месяц» охватывает данные стенда с 23 сентября, когда загружен снимок. Время сборки - с кешем ответов модели от предыдущих сборок того же дня. Запись из источника, который не пускает бота, помечена способом чтения, например «BleepingComputer (прочитан: заголовки браузера)» в выпуске специалисту за неделю. У уязвимостей вектор CVSS расписан словами, у атак индикаторы компрометации и техники MITRE ATT&CK берутся из текста статьи, если он их приводит.

Выпуск, собранный текущей версией, добавляет к записям блоки, которые считает код (DECISIONS, «Что выпуск считает сам» и «Наши системы»):

- под шапкой строка «Вместо ручной работы»: сколько публикаций ассистент просмотрел и сколько это заняло бы аналитика вручную по его журналу, 1,3 с на публикацию периода и 4,6 мин на запись специалисту, 7,2 мин руководству; минуты есть и в YAML, `manual_minutes`;
- у специалиста после «Главного» - «План на смену» (уязвимости и атаки высокого приоритета списком `- [ ]` с действиями из карточки, у невыпущенного исправления первыми идут временные меры) и, если профиль собирал выпуски за последние 30 дней, «Что изменилось с прошлых выпусков»;
- у руководства - «Сутки», «Неделя» или «Месяц в цифрах»: записи по признакам датасета, рядом прошлый выпуск той же длины, если он есть;
- у профиля [ics-security-engineer](profiles/ics-security-engineer.json) шесть «Наших систем» (Siemens, Schneider Electric, ABB PCM600, CODESYS, Cisco, Fortinet): запись о них помечена «касается нас: ...» в строке под заголовком и стоит первой в своей теме.

## Как подборка следует за интересами

Профиль инженера по ИБ АСУ ТП правится тремя способами, по одному за раз, и для каждой правки собирается второй выпуск. В `diff.md` у каждой пришедшей и ушедшей статьи написана причина. Её берёт сам выпуск: у каждого кандидата хранятся оценка, интерес и причина, по которой он не вошёл.

<!-- LATER: счёт «было → стало, пришло, ушло» по пересобранным сценариям -->

| Сценарий | Правка | Было → стало | Что видно |
|---|---|---|---|
| [01-removed-interest](change/01-removed-interest/diff.md) | убран интерес «Уязвимости и обновления безопасности» | 20 → 20: пришло 9, ушло 9 | ушедшие уязвимости с причиной «её интерес убран из профиля», вместо них статьи по оставшимся интересам |
| [02-exclusion](change/02-exclusion/diff.md) | добавлено исключение «уязвимости продуктов Citrix» | 20 → 20: пришло 3, ушло 3 | записи о Citrix ушли с причиной «попадает под исключение» |
| [03-stricter](change/03-stricter/diff.md) | порог 0.50 → 0.70, размер 20 → 10 | 20 → 10 | ушедшие вытеснены более сильными, у каждой её оценка |

Правка интересов или исключений меняет текст профиля, по которому модель оценивает статьи, поэтому все кандидаты оцениваются заново, при температуре 0. Причина каждого ухода и прихода записана в `diff.md`.

## Как пересобрать

```bash
docker compose --profile ollama up -d --build    # с RADAR_LLM_PROVIDER=ollama и ключом облака в .env
uv run scripts/make_examples.py http://localhost:8080 examples
```

Скрипт входит как гость, собирает выпуск по каждому примеру профиля за неделю выше и сценарии смены интересов. На машине из этого репозитория всё вместе заняло около восьми минут. <!-- LATER: время пересборки и команды для выпусков по аудиториям, если пересборка шла иначе -->
