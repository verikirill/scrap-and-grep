# Сравнение моделей

Задание требует, чтобы модель менялась без существенной переработки и основной сценарий сохранялся на другой модели с нужными возможностями. Здесь один сценарий прогнан на нескольких моделях. Профили, неделя примеров (25 сентября - 2 октября 2026 года, снимок [data/samples](../../data/samples/articles.jsonl)) и граф сборки одинаковые. Чтобы сменить модель, меняли только переменные `RADAR_LLM_MODEL`, `RADAR_LLM_BASE_URL` и `RADAR_LLM_REASONING`, код не трогали. Все прогоны сделаны 15 октября 2026 года на текущем коде.

Модели:
- `gpt-oss:120b` - основная, из списка финала; здесь она в облаке Ollama;
- `gpt-oss:20b`, `gemma4:31b` и `nemotron-3-nano:30b` - облако Ollama, ближайшие по классу к Qwen3.6 35B-A3B из задания, которой в облаке Ollama нет;
- `qwen3.5:9b` - локально в стеке, вариант для видеокарты от 8 ГБ;
- автономный режим без модели.

Модели Yandex AI Studio подключаются через OpenAI-совместимый API блоком Yandex AI Studio из `.env.example`, без правки кода; путь проверяет `backend/tests/test_chat.py`. На том же сценарии Qwen3.6 35B в Yandex AI Studio собрала выпуск специалисту за 24 с и выпуск руководству за 17 с, `gpt-oss:120b` в облаке Ollama - за 193 и 113 с. На датасете организаторов Qwen3.6 нашла 24 из 36 признаков руководства и поставила 14 лишних, Alice AI LLM - 22 из 36 и 20 лишних, `gpt-oss:120b` - 23 из 36 и 21 лишний. Таблицы ниже - прогоны в облаке Ollama, в стеке и без модели, их выпуски лежат в папках моделей.

Каждая модель собирала выпуски с пустым кешем ответов, в отдельной базе Valkey, поэтому время сборки сравнимо. Обе `gpt-oss` работали с уровнем рассуждений `low`, остальные модели без рассуждений. Сырые ответы лежат в `<модель>.json` и `<модель>.dataset.json`, выпуски в Markdown - в папке модели.

## Что видно

Сценарий сохраняется на каждой модели: выпуск собран целиком, с разделами «Атаки» и «Уязвимости», карточками, приоритетом по правилу датасета, сверкой с CISA KEV и БДУ и проверкой по тексту. Где модель не дала годного ответа, запись дописал автономный алгоритм: у `gemma4:31b` так написаны 2 текста из 20, у `nemotron-3-nano:30b` 7 из 20, и выпуск вышел полным. Выпуски руководству все модели написали сами, без отката.

Отбор держится на поиске. Даже без модели 16 из 20 записей те же, что у `gpt-oss:120b`, а другие модели расходятся с ней в суждении о 4-7 записях у порога. Два прогона самой `gpt-oss:120b` при температуре 0 совпадают в 17 записях из 20, так что расхождение в три записи - это шум облака.

В датасете все модели прочитали 21 страницу из 21. Тип записи совпал с датасетом в 6-7 примерах из 7, приоритет - в 4 из 7 у `gpt-oss:120b`, `gpt-oss:20b`, `gemma4:31b` и `qwen3.5:9b`, в 3 из 7 у `nemotron-3-nano:30b` и без модели. Признаков руководства модели находят от 20 до 26 из 36. Больше всех их находит `qwen3.5:9b`, 26.

`gemma4:31b` близка к основной модели (16 из 20 у специалиста) и быстрее всех: 98 с на выпуск специалисту против 193 с у `gpt-oss:120b` и 57 с руководству против 113. Это запасной вариант в облаке.

`gpt-oss:20b` в облаке Ollama медленнее старшей: 222 с специалисту и 169 с руководству. Уязвимостями она назвала 15 записей из 19 и высокий приоритет дала семи, с основной моделью совпала в 15 записях.

`nemotron-3-nano:30b` сама инструмент не вызывает: все 50 номеров проверил граф, поэтому справка из баз в выпуске всё равно есть. Проверка убрала из её карточек 10 полей, которых нет в статьях.

`qwen3.5:9b` работает в стеке, на видеокарте 8 ГБ, и собирает выпуск без откатов: специалисту за 188 секунд, руководству за 91. Инструмент она сама не вызывает, 40 номеров проверил граф, и высокий приоритет получили 3 записи против 4-7 у облачных моделей.

`gpt-oss:120b` остаётся основной для примеров: она в списке финала, и на ней собраны все примеры. По умолчанию стек пишет локальной Qwen3.6 35B-A3B: ей хватает карты 12-16 ГБ с частью слоёв на процессоре или карты от 24 ГБ в vLLM, а `gpt-oss:120b` встаёт на одну карту 80 ГБ (README, «Требования к железу»). Если основная модель станет недоступна, запасную `gemma4:31b` включает одна переменная.

### Когда облако занято

На ответ `429 too many concurrent requests` стек не сдаётся: он ждёт и спрашивает снова, шесть повторов с паузой от 2 до 30 секунд, всего около полутора минут (`RATE_LIMIT_RETRIES` в `backend/src/radar/ai/llm.py`). Только после этого вызов считается отказом. После трёх отказов подряд предохранитель отдаёт шаг автономному алгоритму, и выпуск собирается целиком, а его шапка пишет, какую часть сделала модель.

## Как повторить

Локальная модель, например Qwen3.6 35B-A3B из списка финала: стек запущен с ней (README, «Быстрый запуск»), дальше одна команда из корня репозитория:

```bash
backend/scripts/measure_model.sh qwen3.6-35b-a3b
uv run scripts/model_report.py examples/models
```

Скрипт сам очищает кеш ответов и пишет рядом с выпусками `qwen3.6-35b-a3b.hardware.json`: карту, драйвер, пиковую видеопамять, процессор, память и версию Ollama. Токены на вход и выход за выпуск и скорость записи ответа лежат в `qwen3.6-35b-a3b.json`, в поле `usage` у каждого выпуска.

Облачные прогоны выше сделаны так, модель задавалась прямо в команде:

```bash
docker exec -i radar-api-3 sh -c 'cat > /tmp/dataset.json' < docs/task/dataset_v4.0.json
docker exec -i -e RADAR_CACHE_URL=redis://valkey:6379/7 -e RADAR_LLM_MODEL=gemma4:31b \
    -e RADAR_LLM_REASONING=off radar-api-3 python - < backend/scripts/model_compare.py
docker exec radar-api-3 cat /tmp/model_compare.json > examples/models/gemma4-31b.json
docker exec -i -e RADAR_CACHE_URL=redis://valkey:6379/7 -e RADAR_LLM_MODEL=gemma4:31b \
    -e RADAR_LLM_REASONING=off radar-api-3 python - < backend/scripts/dataset_run.py
docker exec radar-api-3 cat /tmp/dataset_run.json > examples/models/gemma4-31b.dataset.json
uv run scripts/model_report.py examples/models
```

Перед каждой моделью база кеша очищается: `docker exec radar-valkey-1 valkey-cli -n 7 flushdb`. В Git Bash перед командами с `/tmp` нужен `MSYS_NO_PATHCONV=1`.
