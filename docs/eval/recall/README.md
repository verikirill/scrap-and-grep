# Что поиск оставил за бортом

Разметка в [human](../human/README.md) и [second-human](../second-human/README.md) оценивает 60 кандидатов, которых нашёл поиск. Она проверяет оценку модели, но не видит новостей, которые поиск не принёс вовсе. Здесь эта часть недели.

| Файл | Профиль | Строк |
|---|---|---|
| [ics-security-engineer.csv](ics-security-engineer.csv) | Специалист по ИБ АСУ ТП | 80 |
| [management-cybersecurity.csv](management-cybersecurity.csv) | Руководство и сотрудники | 80 |

В каждом файле публикации той же недели (25 сентября - 2 октября 2026 года, снимок `data/samples`), которых нет среди кандидатов выпуска. Из них 50 называют ключевое слово профиля (`stratum` = `keyword`), 30 взяты случайно из остальных (`random`). Порядок перемешан.

## Как размечать

Так же, как в [human/README.md](../human/README.md#как-размечать): `grade` от 0 до 3 и `must` = 1, если без этой новости выпуск неполон. Колонки `priority` здесь нет. В первую строку `note` запишите, кто размечал, опыт и время на файл.

## Как посчитать

`must` в этих файлах - важная новость, которую выпуск потерял ещё до модели. Чтобы перейти от выборки ко всей неделе, долю `must` в каждом слое умножают на размер слоя: у специалиста 269 публикаций с ключевым словом и 1 387 без него, у руководства 172 и 1 484. Сборка выборки: `uv run scripts/recall_sample.py <digest.json> <out.csv>`.
