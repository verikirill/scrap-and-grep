# Разметка человеком: заменяет ли ассистент аналитика

Жюри проверяет гипотезу «ИИ-ассистент может заменить аналитика ИБ» в отборе и приоритизации новостей. Ответить на неё может только сравнение с человеком. Здесь лежит всё, чтобы его провести: что размечать, как и чем посчитать. Пункты К1-К3 в [FINAL_PLAN](../../FINAL_PLAN.md).

## Что размечать

Неделя снимка, 25 сентября - 2 октября 2026 года, два профиля:

| Файл для разметки | Выпуск ассистента | Профиль |
|---|---|---|
| [ics-security-engineer.csv](ics-security-engineer.csv) | [ics-security-engineer.digest.json](ics-security-engineer.digest.json) | Специалист по ИБ АСУ ТП, 20 записей |
| [management-cybersecurity.csv](management-cybersecurity.csv) | [management-cybersecurity.digest.json](management-cybersecurity.digest.json) | Руководство и сотрудники, 15 записей |

В каждом файле 60 кандидатов, которые поиск нашёл по интересам профиля: и те, что вошли в выпуск, и те, что нет. Порядок перемешан, оценки модели в файле нет: размечать надо вслепую, не открывая выпуск.

## Как размечать

Откройте файл в Excel или LibreOffice, кодировка UTF-8. Для каждой строки откройте статью по ссылке и заполните три колонки:

- `grade` - оценка по той же шкале, что у модели:
  - 0 - не относится к интересам читателя, реклама, вакансия, пересказ без фактов;
  - 1 - косвенно связана, читать необязательно; сюда же пресс-релизы о партнёрствах и наградах;
  - 2 - по теме интереса, стоит включить в выпуск;
  - 3 - прямо по интересу и требует внимания или действий.
- `must` - 1, если без этой новости выпуск для этого читателя неполон;
- `priority` - только для атаки или уязвимости, по правилу датасета организаторов:
  - атака: `high` - на энергетику или промышленность РФ, `medium` - на другие отрасли РФ, `low` - за рубежом;
  - уязвимость: `high` - есть эксплойт или используется в атаках, `medium` - нет.

В `note` можно написать, почему. Засеките время на файл и запишите его, вместе с именем и опытом размечавшего, в первую строку `note`.

## Как посчитать

```bash
uv run scripts/eval_selection.py score docs/eval/human/ics-security-engineer.digest.json docs/eval/human/ics-security-engineer.csv
```

Скрипт печатает таблицу, её место в `docs/eval/selection.md`:

- точность: доля записей выпуска, которым человек поставил 2 или 3;
- полнота: доля «обязательных» по мнению человека, которые вошли в выпуск;
- nDCG@20: насколько порядок выпуска совпадает с оценками человека;
- совпадение оценок модели и человека и взвешенная каппа;
- совпадение приоритетов атак и уязвимостей.

Шаблон для другой недели или профиля строится из выпуска, сохранённого через `GET /api/v1/digests/{id}`:

```bash
uv run scripts/eval_selection.py template digest.json docs/eval/human/<профиль>.csv
```

## Ассистент против аналитика (К3)

Отдельно от разметки аналитик за ту же неделю вручную собирает выпуск для обоих профилей из тех же источников и засекает время. Третий человек получает оба выпуска без подписей и оценивает полноту, точность, пользу и ошибки фактов. Время ассистента на выпуск видно в его `stats.duration_seconds` (70 с у специалиста и 15 с у руководства на этих выпусках).

## Чего здесь нет

Пока никто не разметил ни одного файла: цифр сравнения с человеком нет, и в документах они не приводятся. Кандидаты ограничены 60, которые нашёл поиск. Новость, которую поиск не нашёл вовсе, в эту разметку не попадёт: для неё нужен полный проход человека по всем публикациям недели.
