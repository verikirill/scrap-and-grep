# Демонстрация

План живого показа на 7 минут. Порядок идёт за данными, как в «Результате полуфинала» [задания](task/TASK.md): исходные материалы, отбор по интересам, выпуск, изменение подборки после правки интересов. Потом репозиторий: что сдано, замена модели, цифры. Модули сверх задания идут последними и только если осталось время.

Каждый раздел интерфейса открывается один раз, к пройденному не возвращаемся. Ждать приходится только сборку выпуска, около 10 секунд, и это время занимает рассказ об этапах сборки.

| # | Где | Время | Что из задания закрывает |
|---|---|---|---|
| 1 | Источники | 0:45 | получать публикации из выбранных источников; показать исходные материалы |
| 2 | Интересы | 1:15 | отбирать по интересам; изменение подборки при изменении интересов |
| 3 | Дайджест | 2:45 | группировать по темам и сохранять ссылки; Markdown и DOCX; результат отбора; инструменты и проверка результатов |
| 4 | Сравнение | 0:40 | изменение подборки при изменении интересов |
| 5 | Репозиторий | 1:00 | код и инструкция запуска, примеры входа и выхода, возможности и ограничения, замена модели |
| 6 | Модули сверх задания | остаток | бизнес-ориентированность |

## Подготовка

Готовить не раньше чем за час до показа. Выпуск собирается за последнюю неделю: чем дольше ждать, тем больше в неё попадёт публикаций, которых модель ещё не оценивала.

1. Стек запущен с моделью. В `.env`:

   ```
   RADAR_EMBEDDING_PROVIDER=ollama
   RADAR_LLM_PROVIDER=ollama
   RADAR_LLM_MODEL=gpt-oss:120b
   RADAR_LLM_BASE_URL=https://ollama.com
   RADAR_LLM_REASONING=low
   RADAR_LLM_CONCURRENCY=4
   RADAR_LLM_API_KEY=<ключ с ollama.com/settings/keys>
   ```

2. Аккаунт для показа готовит скрипт, около 6 минут:

   ```bash
   uv run scripts/demo_prep.py --email <почта> --password <пароль> --fresh
   ```

   Он заводит аккаунт с четырьмя примерами профилей и собирает три выпуска за неделю: для руководства, для специалиста по ИБ АСУ ТП как есть и для него же с исключением, которое на показе добавим руками. Последний выпуск нужен только для того, чтобы ответы модели легли в кеш, и скрипт его удаляет. В конце скрипт печатает, какие записи уйдут из выпуска и какие придут. Если не уходит ничего, значит, на этой неделе нет уязвимостей Citrix: выберите производителя из раздела «Уязвимости» последнего выпуска и запустите скрипт ещё раз с `--exclusion "уязвимости продуктов <производитель>"`.

3. В браузере войти этим аккаунтом и открыть раздел «Источники». Светлая тема. Ширина окна от 1280 CSS-пикселей, иначе история выпусков уедет под выпуск. Во второй вкладке открыть README в GitLab на таблице «Где что посмотреть по заданию».

4. Скопировать в буфер обмена текст исключения ровно так, как его передали скрипту: `уязвимости продуктов Citrix`. С другой буквой это будет другой профиль, и выпуск будет собираться полторы минуты вместо десяти секунд.

5. Запустить Word или LibreOffice, чтобы DOCX открылся сразу.

## 3. Дайджест, 2:45

| Делаем | Говорим |
|---|---|
| Профиль уже выбран, период «Неделя», «Собрать выпуск» | Этапы идут на экране. Поиск по смыслу и по словам по каждому интересу, 60 лучших кандидатов оценивает модель, повторы одной новости склеиваются, записи группируются, модель пишет карточки и тексты, проверка сверяет их со статьёй. Сборка устроена как граф LangGraph с чекпоинтами: если воркер упадёт, сборка продолжится с прерванного шага. Ответы модели кешируются, поэтому повторная сборка занимает секунды, а не полторы минуты. |
| Шапка выпуска | Воронка: сколько публикаций вышло за неделю, сколько стали кандидатами, сколько вошло. «Главное» пишет модель, числа в нём сверены со статьями. В нижней строке написано, какая модель оценивала и писала. |
| Раздел «Атаки» | Порядок задаёт правило датасета: атака на энергетику и промышленность РФ выше атаки на другие отрасли РФ, атака за рубежом ниже всех. Причина приоритета появляется при наведении на чип. В карточке страна жертвы, группировка, отрасли, первоначальный доступ, инструменты, индикаторы. |
| Раздел «Уязвимости», первая запись | Карточка: продукт, версии, обновление, временные меры, эксплойт, CVSS. Строка «Сверено по базам» появилась так: пока модель писала карточку, она вызвала инструмент `lookup_vulnerability`, и тот ответил по каталогу CISA KEV и БДУ ФСТЭК. Номера, о которых модель не спросила, граф проверяет сам. Уязвимость из KEV получает высокий приоритет. Чего нет в тексте статьи, в карточку не попадает: это строка «Нет в тексте» и пометка «убрано проверкой». |
| Прокрутить темы | Остальное разбито на темы, их названия даёт модель. У каждой записи есть «Почему важно» для этого читателя и ссылка на первоисточник, а в «Также об этом» лежат пересказы той же новости в других источниках. |
| Раскрыть «Не вошло в выпуск» | Результат отбора целиком: каждый кандидат с оценкой и причиной. Записи про Citrix помечены как исключённые. |
| Наверх, «DOCX», открыть файл | Тот же выпуск в Word: гиперссылки на источники, карточки, в конце раздел «Как составлен выпуск»: сколько было публикаций, какие модели работали, что поправила проверка. Markdown скачивается соседней кнопкой. |
| Закрыть Word. В «Истории» открыть выпуск «Руководство и сотрудники: кибербезопасность» | Второй формат датасета: без карточек и жаргона, у каждой записи признаки «В РФ», «Ущерб», «Утечка», «Энергетика» и другие из двенадцати в датасете. |

## 6. Если осталось время

Разделы идут в порядке меню, в каждом одно действие:

- «Для вас»: персональная лента между выпусками, у каждой статьи причина, по которой она здесь;
- «Аккаунт»: «Создать ключ» в блоке MCP, и ИИ-ассистент читателя видит его ленту, выпуски и интересы.

Короткое видео по выпуску и публикация в Telegram-каналы требуют подготовки, их показывает README, шаги 7 и 9.

## Если что-то пошло не так

- Сборка идёт дольше 20 секунд. Скорее всего, исключение вставлено не тем текстом, что в подготовке, или подготовка была давно. Продолжаем рассказывать об этапах: с моделью выпуск соберётся примерно за полторы минуты.
- Модель недоступна. Выпуск соберётся в автономном режиме, в шапке появится плашка «Модель была недоступна часть времени». Это и есть устойчивость: показываем плашку и идём дальше.
- В «Сравнении» не те выпуски. В списках «Было» и «Стало» выберите два выпуска «Специалист по ИБ АСУ ТП» с соседними версиями профиля.
